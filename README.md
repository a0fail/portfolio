# Creative Portfolio

Самостоятельный статический сайт на React + TypeScript + Vite. Три страницы: Home / About Me, Web Design, Digital Art. Существующая игра в родительской папке не изменяется.

## Запуск и проверка

Требуется Node.js 22.12+ и npm.

```sh
cd portfolio
npm ci
npm run dev
npm run typecheck
npm run build
npm run preview
```

Если папка портфолио уже является корнем вашего репозитория, `cd portfolio` не нужен. Production-файлы находятся в `dist/`.

## Где редактировать

- `src/data/siteText.ts`: надписи навигации, заголовки страниц, слоган, подписи фото, контактов, фильтра и footer (все тексты из `main.tsx`).

- `src/data/profile.ts`: имя, монограмма, описание, биография, фото и контакты.
- `src/data/webProjects.ts`: игры, их тексты, технологии, вклад, ассеты, ссылки и оформление сообществ.
- `src/data/artworks.ts`: категории, серии, работы и этапы создания.
- `src/data/types.ts`: форматы данных и функция создания заглушек.
- `src/styles.css`: палитра, размеры и адаптивная вёрстка.

В Web Design и Digital Art подключены авторские изображения из `public/assets/`. Заглушки остаются для материалов без файла, например фото профиля. Перед публикацией заполните оставшиеся сведения о разработке игр и ссылки запуска.

## Изображения

Положите файл в соответствующую папку `public/assets/`. Например:

```ts
{
  id: 'illustration-forest',
  src: 'assets/digital-art/illustrations/forest.webp',
  alt: 'Описание реальной иллюстрации для скринридера',
  caption: 'Название работы',
  stage: 'Final', // необязательно
  order: 1, // необязательно; меньшие значения идут первыми
}
```

Указывайте пути без `public/` и без начального `/`. PNG, JPG, WebP, SVG и GIF работают как обычные изображения. GIF сохраняет анимацию, в том числе в просмотрщике. Для первого элемента игровой галереи укажите GIF или скриншот, если GIF нет. У фото путь задаётся в `profile.photo`.

Нет `src` или файл не загрузился — отображается заглушка. Её `aspect` задаёт соотношение сторон, а `tone` — `sage`, `blue`, `purple` или `orange`. Настоящие изображения сохраняют пропорции. В сравнении до/после желательно использовать одинаковый размер холста для обоих баннеров; применяется `object-fit: contain` без растягивания.

## Категории, галереи и работы

В `artworks.ts` добавляйте объекты без изменения JSX:

```ts
{
  id: 'other', category: 'Other', title: 'Other Works', order: 5,
  description: 'Необязательное описание категории',
  projects: [{
    id: 'new-series', title: 'Новая серия',
    works: [{
      id: 'new-work', title: 'Название работы',
      images: [
        { id: 'sketch', src: 'assets/digital-art/graphics/sketch.png', alt: 'Эскиз', stage: 'Sketch' },
        { id: 'line', src: 'assets/digital-art/graphics/line.png', alt: 'Контур', stage: 'Line Art' },
        { id: 'final', src: 'assets/digital-art/graphics/final.png', alt: 'Готовая работа', stage: 'Final' },
      ],
    }],
  }],
}
```

Фильтр создаётся автоматически из `category`. `All` показывает всё. Поле `order` поддерживается для категорий, серий, работ и изображений. Идентификаторы должны быть уникальными среди соседних записей. Можно добавлять любое число изображений в массив `images` игровых и обычных галерей. До/после добавляется объектом в `profkom.comparisons`; поле `aspect` задаёт пропорции окна сравнения (например `1 / 1` для логотипов). Заголовки серий и работ можно опустить, если достаточно заголовка раздела.

## Игры и контакты

Новый игровой проект: добавьте объект формата `Game` в массив `games`, скопировав существующий. Заполните `title`, `description`, `tags`, `images`, `details` и `playUrl`. Дополнительная галерея процесса задаётся через `process: { title, images }`. Первые два проекта оставлены в заданном порядке: Accept Papers Please, Sector 503; после них идут два проекта ВКонтакте.

Пустая `playUrl` делает кнопку недоступной, чтобы не открывать фиктивный адрес. Настоящая ссылка открывается в новой вкладке.

В `profile.contacts` указывайте `value` (видимый адрес/подпись) и `href`: `mailto:ваш@email`, `https://t.me/ваш_ник`, `https://github.com/ваш_профиль`. Пустые ссылки отображаются как текст. Дополнительный GitHub добавляется ещё одним объектом в массив.

## Доступность

Системный шрифт без внешних запросов, видимый фокус, ссылка пропуска навигации, `aria-current`, кнопки фильтра с `aria-pressed`, lazy loading. Lightbox использует нативный modal dialog: Escape, стрелки, свайпы, закрытие по свободному фону, удержание фокуса, блокировка прокрутки и восстановление фокуса. Сравнение использует нативный range: перетаскивание, touch, стрелки, Home/End. Учитывается `prefers-reduced-motion`.

## GitHub Pages

Рекомендуется отдельный репозиторий портфолио: загрузите **содержимое `portfolio/` в корень нового репозитория**, включая скрытую папку `.github/` и `package-lock.json`. Не загружайте `node_modules/` и `dist/`.

1. Основная ветка — `main`.
2. В Settings → Pages → Build and deployment выберите **GitHub Actions**.
3. Push в `main` запускает `.github/workflows/deploy.yml`; можно также запустить его вручную в Actions.
4. Workflow устанавливает зависимости, проверяет TypeScript, собирает сайт, загружает Pages artifact и публикует его.

`base: './'` в Vite обеспечивает относительные пути для корневого сайта и `https://username.github.io/repository-name/`. Страницы используют hash-навигацию (`#/web-design`): прямая ссылка и перезагрузка работают без серверного fallback. Пути к изображениям проходят через `import.meta.env.BASE_URL`.

Если оставляете портфолио внутри существующего репозитория, GitHub не обнаружит workflow внутри подпапки. Перенесите его в корневую `.github/workflows/`, добавьте для npm-шагов `working-directory: portfolio`, у setup-node — `cache-dependency-path: portfolio/package-lock.json`, у upload-pages-artifact — `path: portfolio/dist`. Не включайте одновременно два workflow публикации разных сайтов в один Pages. По умолчанию существующий workflow игры не затрагивается.

Публикация в аккаунт не выполнена: проект подготовлен для вашего репозитория.
